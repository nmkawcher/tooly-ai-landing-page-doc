Tooly AI v1.0.1

A complete guide to setting up, customizing, and publishing your AI-powered multi-tool Flutter application — from first run to store submission.

Tooly AI is a production-ready Flutter app featuring 15+ AI-powered tools including a chat assistant, image generator, OCR image-to-text converter, AI math solver, grammar checker, PDF maker & summarizer, code generator, multi-language translator, email composer, and more. All configuration lives in a small set of centralized files, so you can rebrand and launch quickly.

What's included: Multi-provider AI with automatic fallback (Gemini, Groq, Cohere, Hugging Face, OpenAI, Grok), Firebase Auth, AdMob, a coin-based IAP system, 15 languages, and dark/light theme support.

The app follows a clean BLoC architecture with feature-based modules and utility tool views. Feature-based tools live in lib/features/ and specialized tools live in lib/src/presentation/view/pages/tools/, making it straightforward to add, modify, or remove tools.

Installation

After extracting the project source code, open the root directory in your favorite editor:

1

Open Android Studio or VS Code and select the project root directory.

2

Open the integrated terminal and fetch all dependencies:

pubspec.yaml 
flutter pub get
3

Connect a physical device or start an emulator, then run the app:

Terminal 
flutter run

The app requires a valid android/app/google-services.json (Android) and ios/Runner/GoogleService-Info.plist (iOS) to start Firebase services. See the Firebase Setup section before running for the first time.

App Name

The app name must be updated across three key locations: a central Dart string constant file, the Android manifest, and the iOS configuration plist.

1. Dart Constant

File path: lib/src/utils/constants/m_strings.dart

This is the primary app name string used in appbars, titles, and dialogs across the Dart codebase.

lib/src/utils/constants/m_strings.dart 
class MyStrings {
  static const String appName = 'Tooly AI'; // ← Update your app name here
}

2. Android Label

File path: android/app/src/main/AndroidManifest.xml

Update the android:label attribute on the <application> element to change the title under the launcher icon on Android devices.

android/app/src/main/AndroidManifest.xml 
<application
    android:label="Tooly AI"
    android:name="${applicationName}"
    android:icon="@mipmap/ic_launcher">

3. iOS Display Name

File path: ios/Runner/Info.plist

Find the CFBundleDisplayName key and replace the string value beneath it.

ios/Runner/Info.plist 
<key>CFBundleDisplayName</key>
<string>Tooly AI</string>

App Icon

Generate and replace launcher icons across platforms from a single high-resolution square image.

1

Design a square artwork at 1024 × 1024 px. Avoid transparency — solid backgrounds render best across home screens.

2

Visit appicon.co, upload your image, select both iPhone and Android, then download the ZIP.

3

Android icon resources path: Replace all mipmap-* directories under:

android/app/src/main/res/
4

iOS AppIcon set path: Replace the entire contents of:

ios/Runner/Assets.xcassets/AppIcon.appiconset/
5

In-app asset reference path: Replace the icon image asset at:

assets/images/app_icon.png

This path is referenced in lib/src/utils/constants/m_images.dart as MyImage.appIcon.

Alternatively, configure the flutter_launcher_icons package in pubspec.yaml to automate icon generation.

Package Name

Prior to submitting your app to Google Play or Apple App Store, update the default package identifier to a domain name you control.

Android — build.gradle & Manifest

Gradle configuration file path: android/app/build.gradle

android/app/build.gradle 
android {
    namespace = "com.vertexstation.toolyai" // ← Update your package namespace

    defaultConfig {
        applicationId = "com.vertexstation.toolyai" // ← Update your Application ID
    }
}

Android manifest file path: android/app/src/main/AndroidManifest.xml

Ensure the package attribute on the root <manifest> element matches your applicationId.

iOS — Xcode Project Configuration

iOS Xcode workspace file path: ios/Runner.xcworkspace

Open ios/Runner.xcworkspace in Xcode, select Runner under Targets, go to Signing & Capabilities, and edit the Bundle Identifier.

To safely rename package declarations across all native folders automatically, use the change_app_package_name package via terminal command: dart run change_app_package_name:main com.yourcompany.yourapp.

Firebase Setup

Firebase powers user authentication (Google Sign-In + Guest Anonymous mode) and Cloud Firestore for sync and coin balance management. Connect your own Firebase project following the steps below.

Firebase Service implementation file path: lib/services/firebase_service.dart

Auth Cubit file path: lib/features/auth/presentation/cubit/auth_cubit.dart

Login UI Screen file path: lib/src/presentation/view/pages/auth/login_screen.dart

1

Go to the Firebase Console, create a new project, and register both an Android and iOS app with your package identifier.

2

Android configuration file path: Download google-services.json and place it at:

android/app/google-services.json
3

iOS configuration file path: Download GoogleService-Info.plist and place it at:

ios/Runner/GoogleService-Info.plist
4

In the Firebase Console, go to Authentication → Sign-in method, enable Google Sign-In and Anonymous logins. Register your app's SHA-1 and SHA-256 fingerprints for Android Google Sign-In.

5

Enable Cloud Firestore and Realtime Database in your Firebase project console.

Architecture & Core Services

Tooly AI is architected using GetIt service locator dependency injection, BLoC state management, and modular service utilities.

1. Application Entry Point

File path: lib/main.dart

Initializes Firebase, GetIt DI, RevenueCat IAP, AI Key Managers, Demo Mode, and AdMob before binding global BLoC providers.

2. Dependency Injection Locator

File path: lib/core/di/injection_container.dart

Registers singletons for SharedPreferences, repositories, and factory instances for all Cubits.

3. Route Helper & Navigation

File path: lib/src/config/routes/route_helper.dart

Central route table mapping route constants to screen widgets (splash, onboarding, dashboard, home, login, apiSettings).

4. Demo Mode & Testing Service

File path: lib/services/demo_mode_service.dart

Provides mock AI data, demo coin management, and automatically forces test ads during app store review or development testing.

5. Dashboard & Start Screen

File path: lib/src/presentation/view/pages/dashboard/start_screen.dart

Main navigation shell hosting bottom navigation tabs, tool drawer, and quick feature access.

AdMob Integration

The app supports Banner, Interstitial, and Rewarded video ads powered by Google Mobile Ads SDK. Replace default IDs across three configuration files before launching.

Step 1 — Android App ID

Android manifest file path: android/app/src/main/AndroidManifest.xml

android/app/src/main/AndroidManifest.xml 
<meta-data
    android:name="com.google.android.gms.ads.APPLICATION_ID"
    android:value="ca-app-pub-XXXXXXXXXXXXXXXX~XXXXXXXXXX"/>

Step 2 — iOS App ID

iOS plist configuration file path: ios/Runner/Info.plist

ios/Runner/Info.plist 
<key>GADApplicationIdentifier</key>
<string>ca-app-pub-XXXXXXXXXXXXXXXX~XXXXXXXXXX</string>

Step 3 — Dart Ad Unit IDs

Ad service manager file path: lib/services/ad_manager.dart

Banner Ad Widget file path: lib/src/presentation/view/component/banner_ad_widget.dart

lib/services/ad_manager.dart 
// Banner Ad Unit ID

    : 'ca-app-pub-XXXXXXXXXXXXXXXX/XXXXXXXXXX'; // Production ID

// Interstitial Ad Unit ID
static String get interstitialAdUnitId => _useTestAds
    ? 'ca-app-pub-3940256099942544/1033173712'
    : 'ca-app-pub-XXXXXXXXXXXXXXXX/XXXXXXXXXX';

// Rewarded Ad Unit ID
static String get rewardedAdUnitId => _useTestAds
    ? 'ca-app-pub-3940256099942544/5224354917'

Always test with Google's official test ad unit IDs during testing. Switching to production IDs before testing complete builds will trigger invalid activity policy suspensions.

Submission

Once all branding, API keys, Firebase services, and ad configurations are verified on physical test devices, build production binaries for app store upload.

Pre-Submission Checklist

  • Updated appName in lib/src/utils/constants/m_strings.dart
  • Updated label & package ID in android/app/src/main/AndroidManifest.xml and android/app/build.gradle
  • Updated display name & bundle ID in ios/Runner/Info.plist
  • Replaced icons in android/app/src/main/res/ and ios/Runner/Assets.xcassets/AppIcon.appiconset/
  • Added production android/app/google-services.json and ios/Runner/GoogleService-Info.plist
  • Configured live API keys in lib/services/api_key_manager.dart
  • Replaced test AdMob IDs with production IDs in lib/services/ad_manager.dart
  • Registered Consumable IAP Product IDs in Play Store & App Store Connect
