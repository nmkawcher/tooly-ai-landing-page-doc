Documentation

Tooly AI v1.1.0

A Flutter AI toolkit for Android and iOS with a complete Firebase-only backend: Firebase Authentication, Cloud Firestore and Cloud Functions. No separate server is required.

Tooly AI contains 20 tools: AI chat, translator, code/email/script/social-post/hashtag/CV generators, image generation, AI math solver, grammar fixer, image/PDF/audio/video/website analysis, PDF compression, PDF maker, document-to-PDF conversion, password generator and private notes. Features are paid for with an in-app coin balance.

Architecture in one sentence: the app never contains an AI key or credits coins itself. Every AI request, coin change, purchase verification and account deletion is performed by Cloud Functions (functions/), protected by Firestore security rules (firestore.rules).

Firebase Setup

All backend features use Firebase only. Follow these steps once.

1

Create a project at console.firebase.google.com and upgrade it to the Blaze plan (needed for Cloud Functions; the free quota covers development and small apps).

2

Authentication → Sign-in method: enable Google (select a project support e-mail when asked) and Email/Password.

3

Add the Android app with your package name (default com.example.toolyai), add your SHA-1 and SHA-256 fingerprints (debug and release, and the Play App Signing key), download google-services.json to android/app/.

4

Add the iOS app with your bundle ID, download GoogleService-Info.plist to ios/Runner/ (add it to the Runner target in Xcode) and copy its REVERSED_CLIENT_ID into the CFBundleURLSchemes entry of ios/Runner/Info.plist (this is the Google Sign-In URL scheme).

5

Firestore Database: create a database in production mode. Choose a location close to your users (it cannot be changed later). The required indexes are deployed from firestore.indexes.json.

6

Log in and select your project in the project root:

Terminal
firebase login
firebase use --add
7

Deploy the security rules and indexes:

Terminal
firebase deploy --only firestore
8

Deploy the Cloud Functions - see Cloud Functions & AI Providers.

App Check (recommended)

Firebase App Check makes sure only your genuine app can call your functions. In Firebase console → App Check register Play Integrity (Android) and App Attest / DeviceCheck (iOS). During development run the app once, copy the debug token from the log and add it under Manage debug tokens. When ready, enforce it by setting the function parameter ENFORCE_APP_CHECK=true and redeploying.

Cloud Functions & AI Providers

All server code is in functions/. Provider API keys are stored in Firebase Secret Manager and exist nowhere in the app. Only three providers are supported: Google Gemini, OpenAI and xAI Grok.

1

Install dependencies:

Terminal
cd functions
npm install
cd ..
2

Store your provider keys as secrets. Gemini is the primary provider and is required. For a provider you do not use enter the value disabled:

Terminal
firebase functions:secrets:set GEMINI_API_KEY
firebase functions:secrets:set OPENAI_API_KEY
firebase functions:secrets:set XAI_API_KEY
firebase functions:secrets:set APPLE_KEY_P8

Get keys at Google AI Studio, OpenAI and xAI. APPLE_KEY_P8 is the contents of your App Store Connect In-App Purchase key (.p8), or disabled if you do not ship on iOS yet.

3

Configure non-secret parameters. Create functions/.env.<your-project-id> (git-ignored):

functions/.env.your-project-id
AI_PROVIDER_ORDER=gemini,openai,grok
ANDROID_PACKAGE_NAME=com.example.toolyai
IOS_BUNDLE_ID=com.example.toolyai
APPLE_KEY_ID=
APPLE_ISSUER_ID=
ENFORCE_APP_CHECK=false
GEMINI_MODEL=gemini-flash-latest
OPENAI_MODEL=gpt-4o-mini
GROK_MODEL=grok-4.3
4

Deploy:

Terminal
firebase deploy --only functions

Customising

  • Coin prices per feature, product-to-coin mapping, models, rate limits and blocked-content patterns: functions/config.js. Keep FEATURE_COSTS in sync with FeatureCost in lib/services/firebase_service.dart (display only) and PRODUCT_COINS with lib/services/purchases_service.dart.
  • Models: GEMINI_MODEL, OPENAI_MODEL, GROK_MODEL (defaults in functions/config.js). AI providers retire model IDs regularly; if requests start failing, check firebase functions:log and set a current model ID.
  • Provider order / disabling providers: AI_PROVIDER_ORDER. Media features (images, PDF, audio, video) always use Gemini.

Google Play receipt verification

In Google Cloud console enable the Google Play Android Developer API for your Firebase project. In Play Console → Users and permissions invite the functions service account (YOUR_PROJECT_ID@appspot.gserviceaccount.com) with the permissions View financial data and Manage orders and subscriptions. Create five managed (consumable) products with the IDs starter, basic, popular, premium, ultimate.

App Store receipt verification

Create an In-App Purchase key in App Store Connect → Users and Access → Integrations. Store the .p8 contents in APPLE_KEY_P8 and set APPLE_KEY_ID and APPLE_ISSUER_ID. Create the same five consumable products.

Receipt verification is implemented but needs your store credentials to run. Test with a Play Console license tester / App Store sandbox account before launch.

Firestore Rules

The rules file is firestore.rules (deploy with firebase deploy --only firestore:rules). Summary:

  • users/{uid}: the owner can read; nobody can write from the client, so coins, purchase flags and referral data cannot be tampered with.
  • users/{uid}/notes: owner read/write with field and size validation.
  • transactions: owner read-only. purchases: no client access.
  • reports: create-only, must contain the caller's uid, size limited.
  • Everything else is denied.
firestore.rules (excerpt)
match /users/{uid} {
  allow read: if isOwner(uid);
  allow write: if false;   // Cloud Functions (Admin SDK) only
}
match /transactions/{id} {
  allow read: if signedIn() && resource.data.uid == request.auth.uid;
  allow write: if false;
}

Security Model

RiskMitigation
AI keys extracted from the APK/IPAKeys exist only in Firebase Secret Manager and are used by Cloud Functions. The app has no key and no key-entry screen.
Users editing their coin balanceFirestore rules deny all client writes to wallet data; coins change only inside Cloud Functions transactions.
Fake purchases / replayed receiptsverifyPurchase checks the receipt with Google/Apple and stores each order ID once.
Abuse of the AI proxyAuthentication required, optional App Check, per-user rate limit (20/min), prompt and media size limits, content filtering.
Referral / reward farmingServer-side validation: one referral per account, loop detection, ad-reward cooldown and daily cap.
Data left behind after leavingIn-app Delete account removes all user data (see below).

Content Safety & Reporting

Content filtering

  • Every prompt passes the blocked-pattern list in functions/config.js (BLOCKED_PATTERNS - extend it for your audience) and, when an OpenAI key is configured, OpenAI's free moderation endpoint.
  • Gemini requests use safety settings at BLOCK_MEDIUM_AND_ABOVE for harassment, hate, sexual and dangerous content.
  • Generated text is checked again before it is returned. Blocked requests are refunded and the user sees a clear message.
  • Image prompts are filtered before coins are charged and before the image URL is built.

Reporting

Every AI result screen has a flag (Report) button. The user picks a reason and the report (content, feature, reason, user id, time) is written to the Firestore reports collection. Review reports in the Firebase console (or build an admin view) and take action. Reports are deleted together with the user's account.

No filter is perfect. Review reports regularly, tighten BLOCKED_PATTERNS if needed, and keep your store listing age rating consistent with the content the AI can produce.

Account Deletion

Menu → Delete account (visible when signed in) lets users permanently delete their account, as required by Google Play and the App Store. The user confirms, re-authenticates (Google or password) and the deleteAccount function removes the Firebase Auth user, users/{uid} with its notes, all transactions and reports of that user.

Purchase records in purchases are kept only as anonymous order IDs for fraud prevention. For Google Play, also enter your account deletion URL/steps in the Data safety form.

In-App Purchases

Users buy coin packs with Google Play Billing / StoreKit. The app starts the purchase; the receipt is then sent to verifyPurchase, which verifies it with the store and credits the coins in a transaction. Coins are never credited by the app itself, and the Android purchase is consumed only after the server confirmed it.

Product IDCoins credited
starter100
basic525
popular1100
premium2800
ultimate5750

Create these as consumable / managed products in Play Console and App Store Connect. To change amounts edit PRODUCT_COINS in functions/config.js (authoritative) and the display mirror in lib/services/purchases_service.dart, then redeploy the functions. Credentials: see Cloud Functions.

A verified purchase also sets hasPurchasedPlan, which removes ads for that user.

ProblemSolution
Android build: File google-services.json is missingDownload it from your Firebase project into android/app/ (templates are not used by Gradle).
Google sign-in fails (ApiException: 10 / 12500)Add the SHA-1 and SHA-256 of the keystore you are running with to the Android app in Firebase, re-download google-services.json. For Play-distributed builds add the Play App Signing SHA-1 too.
iOS: Google sign-in crashes or nothing happensPut REVERSED_CLIENT_ID from GoogleService-Info.plist into the URL scheme in Info.plist.
iOS: pod errors / Podfile.lock missingOn a Mac run flutter pub get, then cd ios && pod install --repo-update. The lock file is generated for the exact plugins you install.
"Please sign in" / unauthenticated when using a toolAI tools need a signed-in user. Use Google or the demo email account.
NOT_FOUND / function not foundDeploy the functions (firebase deploy --only functions) to the us-central1 region used by the app, with the same Firebase project as your config files.
Changing the Cloud Functions regionThe app calls functions in us-central1 (Firebase default). To use another region change REGION in functions/index.js and use FirebaseFunctions.instanceFor(region: '...') in Backend.callable (lib/services/firebase_service.dart), then redeploy.
"AI service is temporarily unavailable"Check the function logs (firebase functions:log), that GEMINI_API_KEY is valid and has quota, and that the provider is listed in AI_PROVIDER_ORDER.
App Check errors in debugAdd the printed debug token under App Check → Manage debug tokens, or keep ENFORCE_APP_CHECK=false while developing.
"Not enough coins"Use the daily bonus / coin store, or raise users/<uid>.coins in the Firebase console for test users.
Store products not foundProducts must be active, the app must be uploaded to at least an internal test track and the tester account added as license tester.
Purchase succeeds in the store but no coinsSee function logs of verifyPurchase: usually the Play API access / service account permission or Apple key parameters are missing.
Compressed PDF text cannot be selectedExpected: Compress PDF re-renders pages as images. Choose the "High Quality" level for less loss or keep the original when text must remain selectable.
Document to PDF loses formattingOnly the text of .docx / .txt / .md is converted by design.
flutter pub get version conflictUse the Flutter/Dart versions listed in Requirements, then run flutter clean && flutter pub get.
